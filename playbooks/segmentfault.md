# 思否发布（模板）

> 可复用模板，不含账号或真实文章 ID。AI 在用户登录后先读本文件，再决定发布、草稿、复检与报告。

## 目标

把技术文章发到 SegmentFault 思否。先用 API 建草稿，再在写作页确认并发布；支持标签和原地更新。

## 登录后先确认

1. 打开 <https://segmentfault.com/write>；未登录会跳 `/user/login`。
2. 登录失效立即停，交用户扫码；不碰密码、cookie。

## 内容适配

- 标题写清楚技术问题；正文 Markdown/HTML 按编辑器实际渲染，代码块要标语言。
- 标签 3–5 个，选具体技术词，不堆大词；主线是 `{{profile.mainline}}`，风格按 `{{profile.style}}`。
- 思否偏问答和工程实践：开头给结论，正文给复现步骤、报错、修复和验证。

## 执行

1. 用 `publish_article` 发 `segmentfault`；先 `draft_only=true` 建草稿。
2. 打开草稿/写作页核对标题、正文、标签；由用户点发布，或适配器点发布后回读文章 URL。
3. 发布后回读文章页：标题、正文首段、代码块、标签可见；异常就修。

## 限制

- 没有文章列表接口；用发布结果 URL 或后台确认。
- 草稿接口稳定，正式发布走页面 UI，改版时可能选择器失效。

## 输出

写明文章 URL、标签、草稿/已发布状态。明确写“已做完”；未完成写“未完成 + 原因”。

## 硬约束

图片用思否编辑器上传，不引用仓库直链；不刷问答、不批量灌水。
