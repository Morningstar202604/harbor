# Dev.to 发布（模板）

> 可复用模板，不含账号或真实文章 ID。AI 在用户登录后先读本文件，再决定发布、草稿、复检与报告。

## 目标

用 Forem 官方 API 把技术文章发到 Dev.to，适合中英双语分发和海外读者。

## 登录后先确认

1. 在 Harbor「设置 → 平台账号 → 配置凭据」填 API Key；也可用环境变量 `DEVTO_API_KEY` 覆盖。
2. 先调一次账号信息/文章列表确认 key 有效；401 就停，不反复试。
3. API key 不写进文章、不提交仓库。

## 内容适配

- 正文用 Markdown 原文，代码块标语言；标题和摘要建议英文，正文可中文或双语。
- 标签最多 4 个，小写字母数字、2–30 字符；选 `ai`、`python`、`webdev` 这类平台通用标签。
- 摘要 ≤140 字符；有封面就传 `main_image`。
- 主线 `{{profile.mainline}}`；Dev.to 读者更看重可复现 demo、架构图和踩坑，不要只写观点。

## 执行

1. 用 `publish_article` 发 `devto`；先 `draft_only=true` 存草稿，确认后再发。
2. 发布后回读文章页：标题、正文首段、代码块、标签、封面；草稿则确认 `/dashboard` 里存在。
3. 更新用同一 article id 原地 PUT，不重复发新文。

## 限制

- 标签必须符合平台规则，非法标签会被丢弃。
- 中文标题在英文社区点击率低；需要英文标题/摘要时先改写，不要机翻腔。
- 没有列表分页上限问题；按 API 实际返回处理。

## 输出

写明文章 URL、标签、草稿/已发布状态、封面是否上传。明确写“已做完”；未完成写“未完成 + 原因”。

## 硬约束

API key 只放本机配置；图片用 Dev.to 上传或稳定外链，不引用仓库直链。
